# Архитектура «Пошагового решателя»

Документ для того, кто будет менять код: как разложен один большой файл, где что искать,
по каким правилам устроены движок, генераторы и конструктор вариантов.

- Версия: **4.11.3**
- Файл приложения: `index.html` (~850 КБ, 14 000 строк)
- Плюс один вспомогательный файл: `sw.js` (офлайн-кэш)
- Зависимостей нет. Сборки нет. Сети нет.

---

## 1. Почему один файл

Приложение живёт в школе: его кидают на флешке, открывают с телефона, кладут на диск и в чат класса.
Один файл — это единственная форма, которая доезжает до всех одинаково. Отсюда решения, которые
нельзя менять походя:

- **Никаких внешних ресурсов.** Шрифты, иконки (SVG-спрайт), PDF-движок и шрифт для PDF — внутри.
- **Никакого `fetch`.** Курсы валют вводятся руками; всё остальное считается на месте.
- **Порядок блоков в файле важен.** Скрипт — один IIFE: приватное состояние не видно снаружи,
  наружу торчит только `window.__*` для отладки и автотестов.
- **Совместимость с WebView.** Код пишется так, чтобы работал и в обёртке Android без интернета.

## 3. Путь одного запроса

```
нажатие Enter в поле ввода
    ↓
run(text)                        ← §10, интерфейс
    ↓
solve(text)                      ← §9, главный вход
    ├── detectVar → 'x'
    ├── есть '=' → уравнение
    │       ├── parsePoly("2x + 5") → Poly([5, 2])
    │       ├── parsePoly("13")     → Poly([13])
    │       ├── deg 2 → quadSolution()  (дискриминант, Виет, проверка)
    │       └── deg 1 → linSolution()   (перенос, корень, проверка)
    ├── нет '=' → арифметика / дроби / единицы / геометрия / задача
    └── не понял → честная ошибка с подсказкой, как переформулировать
    ↓
{kind, answer, steps[], answerHtml, numeric}
    ↓
render(res)                      ← §10
    ├── stepsHtml(res.steps)     — шаги с формулами и «Почему?»
    ├── colorizeMath()           — подсветка переменных
    ├── карточки модулей         — график, таблица значений, разбор единиц
    └── LEARN.attempt()          — если задача пришла из тренировки
```

Ключевое правило движка: **он не угадывает**. Если условие не распознано, пользователь получает
объяснение, а не правдоподобный, но неверный ответ. Примеры честных отказов:

| Ввод | Ответ |
|---|---|
| `y = x²` | «это не линейная функция» |
| `x + y = 10` | «в записи две неизвестные, запишите систему через `;`» |
| `√50` | «иррациональное число, точного значения в обыкновенной дроби нет» |
| `20% от 500` | «условие не распознано» — проценты понимаются в словесной формулировке |

## 5. Данные

### Точные дроби вместо float

`0.1 + 0.2 === 0.30000000000000004` — в школьном ответе это недопустимо. Поэтому все числа
в движке идут через `Frac` (числитель/знаменатель, сокращение по НОД), а в десятичную дробь
переводятся только на выводе. `1/2 + 1/3` даёт `5/6`, а не `0,8333333`.

### Схема localStorage

```js
v4.schema       5                 // версия схемы, гоняет миграции
v4.learn        {topics, mistakes, exams, name, font, start}
v4.xp           число опыта
v4.counters     {total, byDay}
v4.hist         история решений за день
v4.achv         список открытых наград
v4.quests       квесты на сегодня
v4.daystreak    {n, d}            // серия дней
v4.theme        light | dark | neon | retro
v4.class        настройки конструктора вариантов
v4.classHist    недавние работы (для чипов «собрать заново»)
v4.gradeTopics  темы класса, если учитель их переопределил
v4.fx           курсы валют и дата
v4.teacher      роль учителя (в пределах сессии — sessionStorage)
v4.errlog       журнал ошибок сессии
solver.*        мелкие настройки решателя (линии, звук и т. п.)
```

`STORE` пишет через `try/catch`: в приватном режиме Safari `localStorage` существует, но падает
на первой записи — тогда данные остаются в памяти и приложение честно предупреждает.

Миграции — объект `MIGRATE` по номеру версии: приводят типы в порядок, чинят «строки вместо чисел»
и не падают, если данных нет. Экспорт прогресса — `snapshot()`, импорт — `restore()`; перенос
между устройствами возможен файлом JSON или коротким кодом.

## 6. Движок: правила, которые нельзя ломать

1. **Порядок перехватов в `solve()` важен.** Линейная функция проверяется **до** системы уравнений,
   иначе `y = 2x + 3` решается как уравнение и даёт `y = −3`.
2. **Никаких «похожих» ответов.** Не распознал — объясни, что именно не так и как переформулировать.
3. **Проверка подстановкой** для уравнений: корень подставляется обратно, и это показывается
   отдельным шагом.
4. **Две неизвестные на одной стороне от `=`** — повод отказаться, а не решать: условие
   `s.split("=").some(sd => /x/.test(sd) && /y/.test(sd))` отсекает `x + y = 10`, но пропускает `y = x² - 1`.
5. **Иррациональное не подменяется десятичной дробью.** `√2` — объяснение, а не `1,414`.
6. **Слова-числа.** «полтора года» = 18 месяцев, «квартал» = 3 месяца, «полгода» = 6 — иначе
   текстовые задачи на деньги разваливаются.

## 7. Генераторы тем (тренировка, тесты, варианты)

Контракт простой:

```js
GEN_TYPES.myTopic = {
  title: "Моя тема",
  make: function(diff){           // diff: 1 — 5–6 класс, 2 — 7–9, 3 — 10–11
    const a = randInt(2, 9);
    return {q: "2x + " + a + " = 14", a: "x = 7", key: "myTopic"};
  }
};
```

Правила, добытые практикой:

- **Только `rand()` внутри IIFE, никакого `Math.random()`.** Генераторы на `Math.random()` рвут
  воспроизводимость: код работы перестаёт давать те же задания на другом устройстве.
  Модули, живущие вне IIFE (линейная функция, `EXTRA`), берут поток через `window.__rand`.
- **Ответ должен проходить числовой чекер.** Целые числа, простые дроби, никаких `y = −5/2`
  в задании, где проверка ждёт число.
- **Не допускать вырожденных записей:** `(x + 0)`, `9x + 0 = 54`, `9/9` — отсеиваются guard-проверками.
- **Порядок тем нормализован** к списку `CLASS_TOPICS`: генераторы тянут случайность из одного
  потока, и от перестановки тем задания съезжают.
- **Перемешивание вариантов ответа — детерминированное** (хеш текста), иначе лист на двух
  устройствах выглядит по-разному.

Всего 24 генератора: `lin`, `lin2`, `quad`, `frac`, `percent`, `motion`, `area`, `work`, `system`,
`units`, `fl_kb`, `fl_point`, `fl_two`, `fl_inter`, `fl_text`, `neg`, `gcd`, `prop`, `abs`, `pow`,
`fsu`, `prog`, `prob`, `round`.

## 8. Прогресс и тренировка

```
попытка (ok, уровень подсказки) → topicState
    ├── last[20]        последние ответы: ok, была ли подсказка, дата
    ├── mastery         % верных без подсказок по последним попыткам
    ├── lvl             1–3: три верных подряд → выше, две ошибки → ниже
    └── srs             повторение 1 → 3 → 7 → 16 → 30 дней; ошибка сбрасывает шаг
```

Из этого набора растёт всё остальное: «Слабые места» (освоение < 80 %), «Повторить сегодня»
(срок подошёл), «Мои ошибки» (открытые и разобранные), уровень, серия дней, квесты и награды.
Контрольная считает баллы: **1** — сам, **0,5** — с подсказкой, **0** — открыл разбор шага;
оценка по процентам 90 / 75 / 50.

## 9. Конструктор вариантов и код работы

### Формат кода

```
K57X - 8 6 2 - 0 0 C 1
 │     │ │ │   └──┬─┘ └ контрольный знак (base32 от строки)
 │     │ │ │      └──── маска тем, 3 знака base32
 │     │ │ └─────────── число вариантов (1…6)
 │     │ └───────────── число заданий (3…10)
 │     └─────────────── класс (0…11)
 └───────────────────── база: зерно ГПСЧ (4 знака, без похожих букв)
```

Алфавит base32 без `I`, `L`, `O`, `U` — чтобы код нельзя было продиктовать с ошибкой.
Класс, число заданий, вариантов и маска тем кодируются **внутри** кода, поэтому на устройстве
ученика работа собирается один в один, даже если там выбраны другие класс и темы.

```js
__clPdf.makeCode("K57X", 8, 6, 2, ["quad","frac"])   // → "K57X-862-00C1" (пример формы)
__clPdf.parseCode("K57X-862-00C1")                   // → {base, grade, per, vars, topics}
__clPdf.parseCode("K57X-862-00C1".slice(0,-1)+"Z")   // → null: контрольный знак не сошёлся
```

Если код не разбирается (старый короткий код или опечатка) — он работает как раньше, просто
как зерно: работа соберётся, но зависит от текущих настроек.

### Сборка вариантов

```
clBuild()
  ├── разбор кода → класс, темы, размер
  ├── нормализация тем к CLASS_TOPICS
  ├── seedRandom(codeToSeed(code) ^ grade*7919)   ← детерминизм
  ├── clMakeVariant() × вариантов: задания по кругу тем, без повторов
  ├── перемешивание внутри варианта
  ├── seedRandom(время)                            ← дальше снова живой поток
  └── clDrawSheets() → листы A4 + ключ
```

Уникальность заданий проверяется строкой вопроса: одно и то же задание не попадёт ни внутрь
варианта, ни в другой вариант.

## 10. PDF и печать

Своего рода самая неочевидная часть: **библиотек нет**.

```
pdfBuilder()  → объекты PDF (страницы, шрифты, текст) → Blob → скачивание
шрифт          DejaVu Sans вшит в файл base64 — поэтому кириллица не превращается в квадраты
```

Два потребителя: `exportPNG` (картинка решения) и `__clPdf` (листы и ключ). В Android-обёртке
вместо скачивания вызывается мост `window.ReshatelApp.savePdf(base64, имя)`.

Печать — отдельная ветка CSS `@media print`: скрыты кнопки, фон, «печати», конфетти; каждый
вариант начинается с новой страницы. Важная грабля: `@media (max-width:760px)` срабатывает
**и в печати** (A4 уже 760 px), поэтому телефонные правила пишутся как
`@media screen and (max-width:760px)`.

## 11. Голос

`window.__speechToMath` переводит услышанное в формулу: числительные с падежами
(«шестнадцати», «двухсот»), «плюс/минус/умножить на/разделить на», «в квадрате», «корень из»,
«скобка открывается», «икс/игрек/зет», «пять девятых», «25 процентов от 200». Пользователь
видит, что услышано и что записано — и может поправить. Озвучка шагов — `speechSynthesis`,
если он есть в браузере; если нет, кнопки просто не показываются.

## 12. Самопроверка

```
__selftest.open()      // окно с результатом
#selftest в адресе     // запуск при загрузке
```

5125 утверждений: разбор уравнений и выражений, все генераторы (по нескольку заданий на тему),
проверка ответов, единицы измерения, форматы кодов работы. Это дешёвый способ поймать регрессию
после правки движка: `__selftest.run()` возвращает `{checked, errors, testBad}` — правильный

## 13. Как добавить новое

### Тему-генератор

```js
GEN_TYPES.myTopic = {
  title: "Моя тема",
  make: function(d){ return {q: "2x + " + randInt(2,9) + " = 14", a: "x = 7", key: "myTopic"}; }
};
```

Дальше тема сама появится в тренировке и тестах. Чтобы она была в конструкторе вариантов,
добавьте её в `CLASS_TOPICS` (ключ и подпись) и в нужные профили `GRADE_PROFILE`.

### Разбор нового типа задач

Добавьте функцию `solveMy(...)` и вставьте её вызов в `solve()` **до** общих веток, вернув
`{kind, answer, steps}` или `null`. Если вернули `null` — движок пойдёт дальше.

### Единицу измерения

```js
{key:"пуд", f:"16.3805", g:"m", stems:["пуд"], names:["пуд","пуда","пудов"],
 note:"пуд — 16,38 кг"}
```

`f` — множитель к базовой единице категории, `g` — род для согласования («16 пудов», «1 пуд»).
Для температур — `kind:"affine"` и коэффициенты `k`, `b`.

### Тему оформления

```css
body[data-theme="mytheme"]{ --bg:#1a1a2e; --ink:#f0f0ff; --line:rgba(240,240,255,.12); }
```

## 14. Производительность и совместимость

- Один поток, без воркеров: движок считает за миллисекунды, тяжёлых циклов нет.
- Панели не пересоздаются: переключение режима — смена класса и обновление содержимого.
- Печать и мобильная вёрстка проверяются на 360/390/430/900/1240 px без горизонтального скролла.
- `localStorage` — единственное хранилище; IndexedDB не используется (PDF собирается в памяти).
- При изменении `index.html` **обязательно поднимать `VERSION` в `sw.js`**, иначе старый файл
  отдаётся из кэша и пользователь не увидит обновления.

## 15. Сборка APK

APK — WebView-обёртка (`com.kibersolver.app`, домен ассетов `appassets.androidplatform.net`)
вокруг того же `index.html`. Порядок, который работает без Gradle:

```
aapt2  → javac → d8 → zip → zipalign -p 4 → apksigner
```

Если нет исходников обёртки, годится и правка готового APK: заменить `assets/index.html`,
поправить в бинарном `AndroidManifest.xml` имя версии (пул строк UTF-16) и `versionCode`,
затем `zip` → `zipalign` → `apksigner` тем же ключом. Проверка после сборки:

```bash
apksigner verify --print-certs -v Решатель.apk
zipalign -c -p 4 Решатель.apk
unzip -p Решатель.apk assets/index.html | md5sum    # совпадает с index.html
```

Ключ подписи — один и тот же от версии к версии, иначе Android не даст обновить приложение
поверх установленного.

## 16. Чек-лист перед выпуском

1. `__selftest.run()` → `5125 / 0 / 0`.
2. Прогнать 5–10 живых формулировок руками: уравнение, дробь, процент, единицы, задача, функция.
3. Проверить печать (A4, без кнопок), мобильную вёрстку 360 px и тёмную/светлую тему.
4. Поднять `VERSION` в `sw.js` и `APP_VERSION` в `index.html`.
5. Собрать APK, проверить подпись и `md5` вложенного `index.html`.
6. Обновить `CHANGELOG.md` и скриншоты, если менялся интерфейс.
